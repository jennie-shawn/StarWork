StarWork Core v0.1 草案

Core 框架与边界结论版

只保留当前已收敛的产品判断：Core 是什么、最小可用形态是什么、多状态如何处理、CLI 如何配合。

一句话 最小地基 两种模式 三个开关 仓库结构 文件边界 CLI 配合 v0.1 结论

一、一句话结论

StarWork Core v0.1 是一套 AI 工作区协议：规定 Agent 进来先读哪里、当前工作放哪里、正式成果放哪里、哪些内容不能乱改。

Core

规则和地基。定义工作区应该长什么样。

CLI

安装工和质检员。负责创建、检查、迁移。

Agent

真正干活的人。按 Core 规则读写项目。

Core 不是一个 App，也不是 CLI 本身；Core 是用户和 Agent 共同遵守的工作区说明书。

二、Core v0.1 最小地基

Core v0.1 不追求大而全。一个工作区只要具备下面三个角色，就可以开始运行。

AGENTS.md
_系统/
  上下文/
    project-status.md
  任务/
    current-work.md
文件 唯一职责 不要放什么
AGENTS.md 跨 Agent 工作规则入口：先读什么、写哪里、哪些边界不能碰。 项目状态正文、任务清单、决策正文。
project-status.md 项目慢变量：目标、阶段、重点、风险、事实源位置。 单次对话记录、事项细节、草稿正文。
current-work.md 当前工作入口：现在做什么、卡在哪里、等谁确认。 长期背景、完整方案、历史流水账。

decisions.md 可以存在，但不是 Core 必需文件。它只记录高影响、已确认、会影响后续多个事项的决策。

三、两种工作模式

Core v0.1 必须兼容两类真实用户：不使用事项的轻量用户，以及需要长期接力的复杂项目用户。

Starter Mode

兼容学员当前模板。适合轻量交付、资料整理、单次产出。

references/        # 原始资料，只读
outputs/drafts/    # AI 待审草稿
outputs/final/     # 用户确认成果

Matter Mode

增强工作追踪。适合长期事项、跨会话接力、过程沉淀。

matters/registry.md
matters/<matter-id>/
  README.md
  progress.md
  notes.md
  drafts/

matters/registry.md 不作为 Core 必需项。一个没有 matter、但具备 Core 最小地基和 Starter Mode 的项目，仍然可以是 StarWork Core 工作区。

启用 Matter Mode 时，应配套 matter-workspace skill，因为事项维护不是建目录这么简单，还包含创建、定位、更新、归档、草稿晋升等动作。

四、三个开关处理多状态

Core 不维护多套版本。所有用户共用同一个 Baseline，只是初始化时打开不同开关。

语言开关

中文路径或英文路径。语义不变，只换目录名和模板语言。

身份与教训开关

单项目放本地；多项目由主库统一维护并分发。

工作追踪开关

Starter 输出模式、轻量事项、完整事项三档。

用户状态 Core 怎么落地 适合谁
中文单项目 Starter 版 中文路径 + 本地身份/教训 + references/outputs 学员当前模板
中文单项目 Matter 版 中文路径 + 本地身份/教训 + 完整事项 想沉淀项目过程的用户
中文多项目完整版 中文路径 + 主库身份/教训 + 完整事项 + 跨项目联络 多卫星项目工作台
英文 Starter 版 英文路径 + 本地身份 + references/outputs 开源和英文用户

状态应该允许升级，不要求用户一开始选到终局。

Starter 输出模式 -> Matter 模式
轻量事项 -> 完整事项
本地 identity/lessons -> 主库分发 identity/lessons

五、Core 仓库如何维护多状态

StarWork 仓库不应该维护多套互相复制的 Core。正确方式是：一套源协议，多个路径 profile，多个可选 capability，再用 preset 组合出用户能直接使用的 kit。

product/core/
├── README.md
├── baseline/              # Core 不变的共同语义
│   ├── spec.md
│   ├── roles.md
│   ├── file-boundaries.md
│   └── health-check.md
├── profiles/              # 同一语义的路径和语言映射
│   ├── zh/
│   │   ├── profile.md
│   │   ├── paths.json
│   │   └── templates/
│   └── en/
│       ├── profile.md
│       ├── paths.json
│       └── templates/
├── capabilities/          # 可启用能力，不复制 baseline
│   ├── starter-outputs/
│   ├── matter-mode/
│   ├── decisions/
│   ├── local-identity/
│   ├── shared-identity/
│   ├── local-lessons/
│   └── shared-lessons/
├── presets/               # 组合配方，给 CLI 和发布套件使用
│   ├── zh-local-starter.yaml
│   ├── zh-local-matter.yaml
│   ├── zh-shared-matter.yaml
│   └── en-local-starter.yaml
└── kits/                  # 给用户直接复制的成品套件
    ├── zh-local-starter/
    ├── zh-local-matter/
    └── en-local-starter/

每层只做一件事

层 职责 维护规则
baseline/ 定义所有 Core 工作区共同遵守的语义。 只写一次，不按语言和用户类型复制。
profiles/ 定义中文、英文等路径和模板语言。 只做映射，不改变 Core 语义。
capabilities/ 定义 Starter、Matter、decisions、identity/lessons 等可选能力。 每个能力独立维护，可被不同 preset 复用。
presets/ 描述某种用户状态由哪些 profile 和 capability 组成。 是组合配方，不放大段模板正文。
kits/ 给用户直接复制的成品目录。 由 preset 组装生成或人工同步，不作为事实源。

核心原则：改规则去改 baseline/；改中文路径去改 profiles/zh/；改事项能力去改 capabilities/matter-mode/；不要去每个 kit 里重复改一遍。

六、关键文件边界

内容 放哪里 原则
项目目标、阶段、风险 project-status.md 低频更新，保持稳定。
现在要做什么、等谁确认 current-work.md 作为下一次接手入口，不写长篇过程。
原始资料 references/ 默认只读，不直接改写来源。
AI 产出草稿 outputs/drafts/ 或 matter 的 drafts/ 未确认前不要混入正式事实源。
确认后的正式成果 项目声明的正式事实源 以正式事实源为准。
高影响决策 decisions.md 可选文件，只写已确认且会长期影响多个事项的判断。

最重要的边界：过程材料不要直接塞进正式事实源；正式事实源也不要变成讨论记录。

七、CLI 如何配合

用户可以不装 CLI，直接复制模板使用 Core。CLI 的价值是把选择、创建、检查和迁移自动化。

starwork init --lang zh --identity local --work starter
starwork init --lang zh --identity shared --matters full
starwork doctor
starwork adapt codex
CLI 能做 Core 负责
根据问答生成目录和模板。 从 presets/ 读取组合配方。
检查缺失、冲突、旧命名。 根据 baseline/ 和 capability 规则判断健康状态。
为 Matter Mode 安装或软链接 skill。 由 capabilities/matter-mode/ 规定启用要求。

八、v0.1 当前结论

  1. Core v0.1 的必需文件先收敛为 AGENTS.md、project-status.md、current-work.md。
  2. matters/ 是增强能力，不是入门必需项。
  3. Starter Mode 兼容学员现有 references/outputs 模式。
  4. 单项目与多项目通过身份/教训来源开关解决，不拆 Core 版本。
  5. 仓库用 baseline + profiles + capabilities + presets + kits 维护多状态。
  6. CLI 以后负责生成、检查、迁移和安装 Matter Mode 所需 skill。
