# Mainflow v0.2：Init / Doctor Skill 瘦身与 References 分层

状态：accepted
日期：2026-06-22
负责人：product-lead
来源：product-mainflow 草案 `_系统/协作/lanes/product-mainflow/workspace/drafts/2026-06-22-mainflow-v0.2-init-doctor-skill-decomposition.md`
关联 Issue：`ISSUE-028`

## 背景

`starworkInit` 和 `starworkDoctor` 已经完成过面向新用户、MultiAgent-only 回流用户的友好起步优化，但主 `SKILL.md` 仍然过长：

- `starworkInit` stable / next 约 620 行。
- `starworkDoctor` stable / next 约 490 行。

这会带来三个实际问题：

- Codex 读取 Skill 时可能分段读取，后半段硬规则更容易漏读。
- 主入口混入完整流程、命令示例、JSON 示例和低频升级细节，注意力被稀释。
- stable / next 双份维护时容易漂移，后续 UX 文案也会继续堆回主 Skill。

MultiAgent v0.13 已证明“短主 Skill + references”的方式更稳定。Mainflow v0.2 应复用同一结构，但不重新设计 Init / Doctor 的用户体验，只做结构瘦身和防漏读治理。

## 目标

将 stable / next 的 `starworkInit`、`starworkDoctor` 从长文档型主 Skill 改为短入口型主 Skill：

- 主 Skill 只保留触发范围、硬安全规则、场景路由、reference 加载表、成功状态口径。
- 长流程、命令细节、报告模板、JSON 示例、低频升级逻辑迁入 `references/`。
- 保留 v0.1 已验收的友好第一屏、MultiAgent-only 回流、安全预览、pending merge 状态分层。

## 非目标

- 不改变 `starwork init` / `starwork doctor` CLI 行为。
- 不新增 CLI 命令。
- 不重新设计 Init / Doctor 的完整 UX。
- 不修改 MultiAgent v0.8+ 的标准线程工具边界。
- 不把 Knowledge / Pack / Host Adapter 的新能力塞进 Init / Doctor 主流程。

## 主 Skill 必须保留

### Init / Doctor 共同保留

- Skill 与 CLI 边界：Skill 负责判断、解释、采访、预览和确认；CLI 负责探测或执行。
- 主入口边界：产品总览、安装入口、能力选择等模糊请求回到 `starwork` 主入口。
- Reference 加载规则：命中具体场景前必须读取对应 reference。
- Reference 缺失停止规则：高风险动作不得继续，提示用户完整安装 StarWork Skills。
- 检查 / 预览 / 写入分层：检查只读；写入前必须 dry-run 或明确确认。
- 不覆盖用户已有业务文件和入口规则。
- 第一屏避免 Core、Pack、Capability、workspace schema、adapter profile 等内部词。
- 成功状态分层：不得把骨架写入、入口待合并、入口生效、MultiAgent 可继续混成一个状态。

### `starworkInit` 主 Skill 必须保留

- 触发范围：创建、接入、初始化项目工作台或项目中心。
- 第一屏说明 StarWork 是给 AI 协作准备的项目工作台，会先确认项目、预览协作文件、确认后写入并 doctor 检查。
- MultiAgent-only 回流第一屏：不是打断多 AI 分工，而是先确认项目、当前任务和写入边界；确认前不改业务内容。
- 默认只问目标目录、新建 / 已有、语言、主要 AI 工具。
- `--yes` 前必须确认绝对路径。
- 已有非空项目必须走 `--agent-docs draft`，不得直接覆盖 `AGENTS.md`、`README.md`、`CLAUDE.md` 或宿主入口。
- dry-run 复述必须包含：准备新增、准备更新、不会改动、需要用户确认。
- pending merge 口径：工作台骨架已写入不等于 AI 入口最终生效。
- 初始化完成后必须运行或建议运行 `starwork doctor --target <path>`。

### `starworkDoctor` 主 Skill 必须保留

- 触发范围：诊断、doctor 结果解释、旧目录整理、升级方案设计。
- `starworkDoctor` 不是 `starwork doctor` 命令本身，也不是 `starwork upgrade` 执行器。
- 历史独立 `starworkUpgrade` Skill 已取消；旧模板升级和 upgrade blueprint 设计由 `starworkDoctor` 承接。
- 检查阶段只读，不自动 repair、upgrade、写入文件。
- MultiAgent preflight 第一屏：先给“多 AI 协作准备度 / 文件影响 / 下一步建议”。
- preflight 缺失项必须翻译成用户影响。
- 诊断表达三段式：我看到的事实、我推测的角色、需要你确认的地方。
- 低置信度判断不得说成事实。
- 用户明确要求升级、生成 blueprint 或 dry-run 后，才进入升级设计。
- 不直接执行 `starwork upgrade --yes`，除非用户明确要求且已完成 dry-run 确认。

## Reference 缺失规则

主 Skill 必须写明：

- 如果命中的 reference 文件不存在或无法读取，高风险动作必须停止。
- 高风险动作包括：写入 `--yes`、执行 upgrade、合并入口规则、修改宿主规则、生成可执行 blueprint。
- 停止时提示“Skill 安装不完整，请重新用完整目录安装 StarWork Skills”，并说明缺失文件路径。

## 验收标准

### 结构验收

- 四个主 `SKILL.md` 行数满足硬上限。
- stable / next 均包含对应 `references/` 目录。
- 主 Skill 中列出的每个 reference 文件真实存在。
- `references/README.md` 说明 reference 缺失停止规则。
- stable / next 的 Init / Doctor reference 文件数量和职责保持一致，next 只允许 channel metadata 或 next 文档口径差异。

### 主 Skill 扫描

主 Skill 必须命中：

- `reference`
- `完整安装`
- `检查 / 预览 / 写入`
- `不会改业务内容` 或同义表达
- `pending merge` 或中文待整合口径
- `MultiAgent`
- `doctor --target`

`starworkInit` 主 Skill 必须命中：

- `MultiAgent-only`
- `--agent-docs draft`
- `绝对路径`
- `dry-run`

`starworkDoctor` 主 Skill 必须命中：

- `只读`
- `不自动 repair`
- `upgrade blueprint`
- `多 AI 协作准备度`

### 主 Skill 禁止回流

主 Skill 不应重新塞回长流程。以下内容应主要在 references 中：

- 完整 JSON blueprint 示例。
- 大段命令序列。
- 完整诊断报告模板。
- 完整旧规则提炼模板。
- 长篇 Pack / Knowledge / Host Adapter 说明。

### 用户体验验收

- Init 第一屏仍能解释 StarWork 是什么、接下来做什么、写入前如何确认。
- MultiAgent-only 回流仍解释“先安全接入，不是打断多 AI 分工”。
- Doctor 仍有 MultiAgent preflight 结论层。
- Doctor 检查阶段仍明确只读、不改文件。
- pending merge 仍区分“骨架已写入”和“AI 入口尚未最终生效”。

### 回归验收

Development 回传必须包含：

- 修改文件列表。
- 四个主 Skill 行数。
- references 树。
- 关键文本扫描结果。
- 验证命令结果：

```bash
node --check product/cli/src/cli.js
node --check product/cli/test/init.test.js
git -C product diff --check
node --test product/cli/test/init.test.js --test-name-pattern "mainflow|init|doctor|skill|reference|friendly"

```
