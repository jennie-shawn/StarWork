# MultiAgent v0.2 验收报告

日期：2026-06-01

结论：核心验收通过，保留一个 `instruct` 稳定性优化项。

## 验收重点

- `starwork multiagent status --host` 能否读取 Codex thread 状态。
- `starwork multiagent read <lane>` 能否读取目标 lane 绑定的 Codex thread。
- `starwork multiagent instruct <lane>` 能否按格式向目标 Codex thread 发送跨会话指令。
- `starwork multiagent launch <lane>` 是否能创建、初始化并绑定 Codex thread。
- 中文 / 英文项目是否使用对应协作路径。
- 自动消息是否使用 `<!-- STARWORK:MULTIAGENT_MESSAGE v1 -->` 标记，并只保留 `## 消息内容`。

## 最终验收结论

第三次验收中，第二次验收发现的 `launch` 绑定时机问题已修复。

已通过：

- `npm test` 通过：71 个测试全部通过。
- `git -C product diff --check` 通过。
- `status --host` 通过，能读取真实 Codex thread。
- `status --host --load` 重试 3 次均通过。
- `read <lane>` 通过，能读取真实 turns。
- `launch <lane> --yes` 通过，能创建 thread、发送 Launch Message、写入 binding。
- `read launch-test` 通过，能读到新建 thread 的 1 个 completed turn。
- `launch` 回归测试通过：Launch Message 失败时不写入 binding。
- `launch` 回归测试通过：最终验证 read 超时但 turn completed 时允许绑定，并标记 `verified_by_thread_read: false`。
- `instruct <lane> --yes --timeout 90000` 通过，返回 `completed`，随后读取目标 thread 可见 completed turn。

保留优化项：

- 一次默认 timeout 的 `instruct --yes` 返回 `sent`，随后读取目标 thread 发现该 turn 为 `interrupted`。
- 这说明 “sent 但未 completed” 对用户来说语义不够安全，需要单独优化。

## 真实复验记录

### status / read

绑定真实测试 thread 后：

```bash
starwork multiagent status --host --target <tmp> --json
starwork multiagent status --host --load --target <tmp> --json
starwork multiagent read development --turns 2 --target <tmp> --json
```

结果：

- `development` lane 可读到真实 Codex thread。
- host 状态为 `idle`。
- 能读取真实 `cwd`、`turn_count` 和最近 turns。

### launch

执行：

```bash
starwork multiagent launch launch-test --target <tmp> --json --yes
```

返回：

```json
{
  "lane": "launch-test",
  "adapter": "codex",
  "status": "completed",
  "thread_id": "019e83cb-adf1-7d90-804d-d9e12bff782e",
  "turn_id": "019e83cb-ae0d-78e2-ae12-48a46f6cd595",
  "verified_by_thread_read": true
}
```

随后读取：

```bash
starwork multiagent read launch-test --turns 3 --target <tmp> --json
```

结果：

- `readable: true`
- `status: idle`
- `cwd` 为临时 StarWork 项目目录
- 最近 turn 为 `completed`
- `agent-lanes.md` 和 `.starwork/agent-lanes/state.json` 已绑定成功 thread

### instruct

默认 timeout 下有一次返回：

```json
{
  "status": "sent",
  "verified_by_thread_read": false,
  "verification_warning": "Codex app-server did not return response 5"
}
```

随后读取目标 thread，看到该 turn 为 `interrupted`。

使用更长 timeout 复测：

```bash
starwork multiagent instruct development \
  --from product-planning \
  --message "验收复测二：请只回复“收到 MultiAgent 复测二”。不要修改任何文件。" \
  --target <tmp> \
  --json \
  --yes \
  --timeout 90000
```

返回：

```json
{
  "host_delivery": {
    "status": "completed",
    "verified_by_thread_read": true,
    "verification_warning": null
  }
}
```

随后读取目标 thread，可见该 turn 为 `completed`。

## 产品判断

MultiAgent v0.2 的核心能力已经具备验收通过条件：

- 可以观察其他 lane 的 Codex thread。
- 可以读取其他 lane 的最近执行状态。
- 可以 launch 新 lane thread，并在初始化完成后写入 binding。
- 可以发送跨会话指令；在足够 timeout 下可完成并验证。

但 `instruct` 默认 timeout 下的 `sent` 状态仍需优化，避免用户误以为任务已稳定交付。
