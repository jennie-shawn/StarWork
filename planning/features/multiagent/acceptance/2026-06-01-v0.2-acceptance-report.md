# MultiAgent v0.2 验收报告

日期：2026-06-01

结论：暂不通过。

## 验收重点

- `starwork multiagent status --host` 能否读取 Codex thread 状态。
- `starwork multiagent read <lane>` 能否读取目标 lane 绑定的 Codex thread。
- `starwork multiagent instruct <lane>` 能否按格式向目标 Codex thread 发送跨会话指令。
- `starwork multiagent launch <lane>` 是否能创建并绑定 Codex thread。
- 中文 / 英文项目是否使用对应协作路径。
- 自动消息是否使用 `<!-- STARWORK:MULTIAGENT_MESSAGE v1 -->` 标记，并只保留 `## 消息内容`。

- `launch --dry-run` 输出格式化 Launch Message。

## 阻塞问题

真实 Codex app-server 验证未通过。

当前实现使用 `spawnSync("codex", ["app-server", "--listen", "stdio://"], { input })` 一次性写入多条 JSON-RPC 消息，然后关闭 stdin。真实 app-server 只稳定返回 `initialize`，后续 `thread/list`、`thread/read`、`thread/resume`、`turn/start` 可能被丢弃。

复现结果：

```text
starwork multiagent status --host --target <tmp> --json
```

目标 lane 已绑定 Codex thread，但返回：

```json
{
  "adapter": "codex",
  "readable": false,
  "status": "notLoaded",
  "warning": "Codex app-server did not return thread/read"
}
```

真实发送：

```text
starwork multiagent instruct development --from product-planning --message "..." --target <tmp> --json --yes
```

返回：

```json
{
  "host_delivery": {
    "adapter": "codex",
    "status": "failed",
    "warning": "Codex thread/read failed before send"
  }
}
```

对照验证：用长连接方式启动 `codex app-server --listen stdio://`，先发送 `initialize`，等待返回后再依次发送 `thread/list`、`thread/read`、`thread/resume`，真实 app-server 可以返回数据。因此问题不在 Codex 能力本身，而在 CLI 的 app-server 调用方式。

## 其他问题

- `listCodexThreads()` 当前按 `response.result?.threads || response.result` 解析，但真实 `thread/list` 返回结构是 `result.data`。即使后续改为长连接，也需要修正解析逻辑。
- `multiagent share` 完成提示仍硬编码 `_系统/协作/shared.md`，英文工作区应该提示 `_system/collaboration/shared.md`。
- `product/skills/starworkMultiagent/SKILL.md` 的先读路径和 workspace 说明仍以中文路径为主，需要补充英文镜像说明，避免 Agent 在英文项目里误读路径。

## 验收建议

v0.2 需要回到开发 lane 修复后再次验收。

修复方向：

- Codex app-server adapter 改为长连接 / 顺序 JSON-RPC 调用：发送一条，等待对应 response 或事件，再发送下一条。
- `status --host --load` 应显式 `thread/resume` 后再 `thread/read`。
- `instruct` 应在 `thread/resume` 成功后 `turn/start`，并等待 `turn/completed` 或超时。
- 单测中的 fake codex 需要模拟真实 app-server 的异步行为，避免一次性 stdin 输入误判通过。
- 修复 `thread/list` 的 `result.data` 解析。
- 修复英文镜像路径提示和 skill 文档路径说明。
