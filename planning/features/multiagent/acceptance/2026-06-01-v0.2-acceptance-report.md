# MultiAgent v0.2 验收报告

日期：2026-06-01

结论：部分通过，暂不通过发布验收。

## 验收重点

- `starwork multiagent status --host` 能否读取 Codex thread 状态。
- `starwork multiagent read <lane>` 能否读取目标 lane 绑定的 Codex thread。
- `starwork multiagent instruct <lane>` 能否按格式向目标 Codex thread 发送跨会话指令。
- `starwork multiagent launch <lane>` 是否能创建、初始化并绑定 Codex thread。
- 中文 / 英文项目是否使用对应协作路径。
- 自动消息是否使用 `<!-- STARWORK:MULTIAGENT_MESSAGE v1 -->` 标记，并只保留 `## 消息内容`。

## 再次验收结论

第一次验收发现的真实 app-server 通信问题已经修复。真实 Codex thread 上：

- `status --host` 通过，能读取绑定 thread 的名称、cwd、状态和 turn 数。
- `status --host --load` 通过，能显式加载 thread 后读取状态。
- `read <lane>` 通过，能读取最近 turns。
- `instruct <lane> --yes` 通过，返回 `host_delivery.status: completed`，并且 `verified_by_thread_read: true`。
- `launch <lane> --yes` 未通过：能创建新 thread id，但初始化消息发送失败，且仍把 lane 绑定到失败 thread。

阻塞点已经从“真实 Codex app-server 无法通信”收敛为“launch 失败处理和绑定时机不正确”。

## 阻塞问题

`multiagent launch` 真实 Codex app-server 验证未通过。

复现命令：

```text
starwork multiagent launch launch-test --target <tmp> --json --yes
```

返回：

```json
{
  "schema": "starwork.agent_lanes.launch.v0.2",
  "launches": [
    {
      "lane": "launch-test",
      "adapter": "codex",
      "status": "failed",
      "thread_id": "019e83a5-2ea7-7321-bb59-a1c1fc54e993",
      "warning": "Codex app-server did not return response 5"
    }
  ]
}
```

但 registry 已被写入：

```text
| launch-test | 待补充 | codex:019e83a5-2ea7-7321-bb59-a1c1fc54e993 | 待补充 | lanes/launch-test/worklog.md | lanes/launch-test/workspace |
```

随后读取该 lane：

```json
{
  "lane": "launch-test",
  "starwork": {
    "session": "codex:019e83a5-2ea7-7321-bb59-a1c1fc54e993"
  },
  "host": {
    "readable": false,
    "status": "notLoaded",
    "warning": "thread not loaded: 019e83a5-2ea7-7321-bb59-a1c1fc54e993"
  }
}
```

这说明 `launch` 失败后仍把 `agent-lanes.md` 和 `.starwork/agent-lanes/state.json` 更新成了新 thread binding。用户会看到 lane 已绑定，但目标 thread 没有完成初始化，后续 `read` 也读不到可用状态。

## 验收建议

v0.2 需要回到开发 lane 修复 `launch` 后再次验收。

修复方向：

- `launch` 必须明确绑定时机：只有 Launch Message 发送成功，才写入 lane binding；发送失败时不要把失败 thread 绑定成当前 lane。
- 如果产品上希望保留失败 thread，也必须显式记录为 `created_but_not_initialized`，并在 `agent-lanes.md` 中保持 `unbound`。
- `launchCodexLane()` 里的 `sendCodexInstruction()` 不应因为最后一次 `thread/read` 超时就直接判定初始化失败，除非 `turn/start` 或 `turn/completed` 确实失败；需要区分“消息已完成但验证 read 失败”和“消息未送达”。
- 单测需要新增 launch 失败场景：thread 创建成功、初始化消息失败时，不得写入 binding。
- 修复英文镜像路径提示和 skill 文档路径说明。
