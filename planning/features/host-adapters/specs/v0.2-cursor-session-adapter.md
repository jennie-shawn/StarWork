# Host Adapter v0.2：Cursor 会话读取与 Trae 人工操作 SPEC

## 1. 状态

- 日期：2026-06-04
- 状态：ready-for-development
- 所属功能：Host Adapters / MultiAgent
- 关联文档：
  - `product/planning/features/host-adapters/specs/v0.1-implementation.md`
  - `product/planning/features/multiagent/specs/v0.4-runtime-host-routing.md`
- 影响模块：`starwork multiagent read/status/instruct/continue/launch`、`starwork doctor --host cursor|trae`、`product/adapters/cursor|trae/profile.json`

## 2. 需求结论

本版本只处理两个明确需求：

1. Cursor：适配“读取会话 transcript”的能力，用于 lane 回溯、审计和状态观察。
2. Trae：停止继续适配会话能力。检测到 Trae 或绑定 `trae:<id>` 时，直接转人工操作。

本版本不实现 Cursor 跨会话发送、Cursor 新建会话、Trae 会话探测、Trae transcript 读取或 Trae 元数据观察。

## 3. Cursor 会话读取

### 3.1 已知事实

用户在 Cursor 中实测确认：

- 同项目会话 transcript 可从 `~/.cursor/projects/<project-key>/agent-transcripts/<uuid>/<uuid>.jsonl` 只读获取。
- transcript 可还原用户消息、部分助手文本、工具调用名称和工具 input。
- transcript 通常缺少完整 stdout / stderr、被读取文件全文、图片和终端截图。
- 当前未发现 Cursor MCP / Agent 工具可向另一条 IDE 会话投递消息。
- `cursor agent --resume <uuid> "<prompt>"` 需要登录，且即使可运行也不等同于向已打开 IDE chat 标签投递消息。
- 写入 `agent-transcripts/*.jsonl` 不会触发会话，且会污染宿主日志。

### 3.2 CLI 行为

当 lane 绑定为 `cursor:<uuid>` 时：

```bash
starwork multiagent read <lane> --target <workspace> --json
```

CLI 应只读解析绑定会话的 Cursor transcript，并输出受控摘要：

```json
{
  "host": "cursor",
  "status": "transcript_observed",
  "session_id": "e1717037-1b15-411b-8665-ae922b421f74",
  "transcript_path": "~/.cursor/projects/<project-key>/agent-transcripts/<uuid>/<uuid>.jsonl",
  "line_count": 32,
  "first_user_query": "请开始根据 ... 工作",
  "last_user_query": "若存在则输出最近用户消息",
  "tool_names": ["ReadFile", "Shell", "ApplyPatch"],
  "candidate_outputs": ["product/docs/multiagent/cursor-session-management-research-result.md"],
  "warning": "Cursor transcript is incomplete host observation; StarWork worklog/shared remain the source of truth."
}
```

解析要求：

- 只读 `agent-transcripts/<uuid>/<uuid>.jsonl`。
- 支持 NDJSON，遇到坏行时跳过并记录 warning，不让整个命令崩溃。
- 不输出完整 JSONL。
- 不输出大段 patch 正文。
- 不写入 transcript、Cursor 私有数据库或 workspace storage。
- 不把 transcript 自动写入 StarWork worklog。

状态要求：

| status | 含义 |
| --- | --- |
| `transcript_observed` | 找到并成功摘要绑定 session transcript |
| `not_found` | 未找到 transcript root 或绑定 UUID 文件 |
| `unreadable` | 文件存在但不可读 |
| `malformed_partial` | 文件部分可解析，部分坏行已跳过 |
| `manual_handoff_required` | 用户请求的是发送、继续执行或无法从 transcript 满足的动作 |

### 3.3 `status --host`

当存在 Cursor adapter 或绑定 session 为 `cursor:<uuid>` 时：

```bash
starwork multiagent status --target <workspace> --host --json
```

CLI 应报告：

- Cursor adapter 是否启用。
- `.cursor/rules/starwork.mdc` 是否存在。
- `.cursor/skills/` 是否存在。
- `~/.cursor/projects/<project-key>/agent-transcripts/` 是否存在。
- 当前绑定的 `cursor:<uuid>` transcript 是否存在。
- `cursor` CLI 是否存在。
- `cursor agent status` 是否登录。
- `CURSOR_API_KEY` 是否设置，只输出 boolean，不输出密钥值。

`status --host` 可以展示 Cursor CLI resume 的认证状态，但不得把它解释成自动跨会话投递能力。

### 3.4 Cursor 不做项

本版本不做：

- 不向另一条 Cursor IDE 会话自动发送消息。
- 不实现 `multiagent instruct` 的 Cursor 自动投递。
- 不把 `cursor agent --resume` 包装成 `instruct` 成功。
- 不实现 Cursor `launch` / `create-chat`。
- 不写 `agent-transcripts/*.jsonl`。
- 不读取或改写 Cursor 私有数据库。
- 不承诺打开、切换、置顶、归档或删除 Cursor 历史会话。

对 `cursor:<uuid>` 执行 `instruct` 时，仍应返回 `manual_handoff_required`，并生成可复制的 handoff message。

## 4. Trae 人工操作

### 4.1 产品决策

Trae 不再继续做会话能力适配。

原因：

- 当前未确认 Trae 有稳定公开的跨会话投递 API。
- Trae 完整聊天内容涉及加密或私有存储，不应作为 StarWork 读取目标。
- 观察型元数据适配对 MultiAgent 闭环价值有限，容易让用户误以为 StarWork 能自动操控 Trae 会话。

### 4.2 CLI 行为

只要检测到目标宿主为 Trae，或 lane 绑定为 `trae:<id>`，MultiAgent 会话相关命令统一转人工：

| 命令 | Trae 行为 |
| --- | --- |
| `multiagent read <lane>` | 返回 `manual_handoff_required` 或 `unsupported`，提示读取 StarWork worklog/shared，不读 Trae 会话 |
| `multiagent status --host` | 返回 `manual_host`，说明 Trae 仅支持 StarWork 项目内协作记录和人工操作 |
| `multiagent instruct <lane>` | 返回 `manual_handoff_required`，生成可复制消息 |
| `multiagent continue <lane>` | 返回 `manual_handoff_required`，提示用户在 Trae UI 中手动打开/继续会话 |
| `multiagent launch <lane>` | 返回人工启动步骤，不尝试创建 Trae 会话 |

Trae 的 `host_status` 建议统一为：

```json
{
  "host": "trae",
  "status": "manual_host",
  "message": "Trae host session automation is not adapted. Use StarWork worklog/shared context and manual UI operation."
}
```

### 4.3 Trae 不做项

本版本不做：

- 不读取 Trae `database.db`。
- 不读取 Trae `state.vscdb` 作为 MultiAgent session 元数据来源。
- 不枚举 Trae session。
- 不读取 Trae transcript。
- 不继续做 Trae observation probe。
- 不实现 Trae `launch`、`continue`、`instruct` 自动化。
- 不写入 Trae 私有状态。

现有 `starwork adapt trae` 若保留，只能负责 StarWork 可控入口，例如 `.trae/rules/`、`.trae/skills/` 和 `.agents/skills/`；不得暗示 Trae 会话自动化已适配。

## 5. Profile 调整

### 5.1 Cursor

Cursor profile 中 session 能力应收敛为：

```json
{
  "sessions": {
    "detect_current": "partial",
    "list": "partial",
    "read": "partial",
    "continue": "manual",
    "send_message": "manual",
    "create": "unsupported",
    "rename": "partial",
    "pin": "unsupported",
    "archive": "unsupported"
  },
  "memory": {
    "transcript_read": "partial",
    "transcript_write": "unsupported"
  }
}
```

解释：

- `read=partial` 仅表示可以读取本地 transcript 摘要。
- `continue=manual` 表示可提示用户使用 UI 或登录后的 CLI resume，但不自动代替业务交付。
- `send_message=manual` 表示所有跨会话指令都走 handoff。

### 5.2 Trae

Trae profile 中 session 能力应收敛为：

```json
{
  "sessions": {
    "detect_current": "unsupported",
    "list": "unsupported",
    "read": "unsupported",
    "continue": "manual",
    "send_message": "manual",
    "create": "unsupported",
    "rename": "unsupported",
    "pin": "unsupported",
    "archive": "unsupported"
  },
  "memory": {
    "transcript_read": "unsupported",
    "transcript_write": "unsupported"
  }
}
```

解释：

- `continue=manual` 和 `send_message=manual` 只表示 CLI 生成用户可复制的人工操作说明。
- `detect_current=unsupported` 表示不再读取 Trae 私有存储来识别当前会话。

## 6. 验收标准

开发完成后，product-planning lane 按以下标准验收：

1. 绑定 `cursor:<uuid>` 后，`multiagent read <lane> --json` 能从 fixture 或真实 Cursor transcript 输出受控摘要。
2. Cursor transcript 缺失时返回 `not_found`，不报假成功。
3. Cursor transcript 含坏行时返回 `malformed_partial` 或 warning，并保留可解析内容。
4. Cursor `status --host --json` 不泄露 `CURSOR_API_KEY`，只输出是否存在。
5. Cursor `instruct` 仍返回 `manual_handoff_required`，不使用 CLI resume 冒充自动发送。
6. 对 `trae:<id>` 执行 `read/status/instruct/continue/launch` 均进入人工或 unsupported 路径。
7. Trae 路径不读取 `database.db`、`state.vscdb` 或其他私有会话存储。
8. `starworkMultiagent` Skill 只解释 CLI 返回状态，不硬编码 Cursor / Trae 私有路径。
9. README / A 测指南表达清楚：Cursor 只支持 transcript 只读回溯；Trae 是人工操作宿主。
