# M2.9 Knowledge Capability 备忘

## 背景

本备忘记录一次产品判断：StarWork 当前的 `知识/knowledge/` 结构过于简单，容易被理解成普通资料夹；但真正有价值的知识库应是由 Agent 持续维护、整理、重组和健康检查的长期理解层。

参考材料：

- Andrej Karpathy, [LLM Wiki](https://gist.githubusercontent.com/karpathy/442a6bf555914893e9891c11519de94f/raw/ac46de1ad27f92b28ac95459c782c07f6b8c964a/llm-wiki.md)

## 初步结论

知识库不应继续被当作基础 Kit 的默认文件夹来理解。

更合理的定义是：

> 参考资料是输入，成果是输出，知识库是 Agent 持续维护的长期理解层。

因此，知识库应逐步收敛为类似 `multiagent` 的可插拔能力：

```text
Project Workspace
+ Knowledge Capability
= 带知识库能力的项目工作台
```

项目中心也可以开启共享知识库能力：

```text
Project Center
+ Shared Knowledge Capability
= 带共享知识库的项目中心
```

## 概念边界

| 概念 | 含义 | 默认性 |
|---|---|---|
| 参考资料 | 用户给当前项目使用的原始资料，例如文章、会议记录、PDF、网页、截图。 | 项目工作台默认有 |
| 输出/草稿 | Agent 工作过程、方案、中间版本。 | 项目工作台默认有 |
| 输出/确认成果 | 用户确认后的项目成果。 | 项目工作台默认有 |
| 项目知识库 | 当前项目内被提炼、组织和持续维护的长期知识层。 | 可选开启 |
| 项目中心共享知识库 | 跨项目复用的共享知识层。 | 项目中心可选或默认能力，待定 |
| 知识候选 | 项目中产生、准备提交到项目中心共享知识库的候选内容。 | 由工作流产生 |

关键边界：

- `参考资料/` 不是知识库。
- `输出/确认成果/` 也不是知识库。
- 知识库不是简单存文件，而是需要维护结构、索引、交叉引用、摘要和健康状态。

## 建议的能力形态

用户侧表达：

```text
开启知识库
```

内部表达：

```text
knowledge capability
shared-knowledge capability
```

能力开启后，知识库可以包含类似结构：

```text
知识库/
├── index.md        # 知识目录，按主题/实体/概念组织
├── log.md          # 维护日志，记录 ingest/query/lint/synthesis
├── schema.md       # 当前知识库维护规则
├── sources/        # 原始资料索引或链接，不一定复制原文
├── pages/          # Agent 维护的主题页、实体页、概念页
├── synthesis/      # 综述、比较、阶段性结论
└── inbox/          # 待处理资料或待吸收问题
```

这只是后续设计参考，不代表本轮立即落地结构。

## 配套 Skill 方向

后续可设计 `starworkKnowledge` skill，用于管理知识库工作流，而不是简单整理资料。

可能能力：

| 能力 | 含义 |
|---|---|
| Ingest | 吸收新资料，摘要、拆主题、更新相关页面、更新 index 和 log。 |
| Query | 基于 index 和知识页回答问题，必要时沉淀新的知识页。 |
| Synthesize | 对多个来源生成综述、比较、趋势判断、人物/概念关系。 |
| Lint | 检查知识库健康度，例如矛盾、过期、孤立页面、缺少引用。 |
| Promote | 将项目知识库中的可复用知识提交到项目中心共享知识库候选区。 |

## 对现有 StarWork 的影响

后续需要讨论：

1. Project Kit 是否默认移除 `知识/`。
2. 项目中心是否默认带共享知识库能力。
3. `doctor` 是否不再把缺少 `知识/` 视为结构问题。
4. `upgrade` 遇到旧 `知识/` 时，应判断它是普通资料夹、项目本地知识库、项目中心共享知识库，还是旧模板残留。
5. `spawn` 创建中心管理的项目工作台时，是否根据项目中心配置挂载共享知识库。
6. 是否新增 `starworkKnowledge` skill。

## 暂定产品原则

1. 知识库是能力，不是基础目录。
2. 知识库由 Agent 持续维护，不只是存放资料。
3. 原始资料、工作过程、确认成果和可复用知识必须分层。
4. 项目知识库和项目中心共享知识库要区分。
5. 知识回写到项目中心前，应经过候选和审核流程。
